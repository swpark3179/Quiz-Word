# Quiz Word — 시험 영어 단어장

시험 문제 파일에 나온 영어 단어를 문제 속 뜻·예문과 함께 익히는 로컬 단어장입니다.

- **단어 사전은 하나**(뜻·품사·발음·외우기·난이도)이고, **예문·출현 횟수·노트는 시험별로** 따로 둡니다. 같은 단어가 여러 시험에 나와도 사전은 한 번만 적고, 보고 있는 시험의 예문이 나옵니다.
- 지금 들어 있는 시험: **CCAR-F** (문제 파일 7개). 다른 시험은 [새 시험 추가](#새-시험-추가)로 얹습니다.

## 실행

[Node.js](https://nodejs.org) LTS(22 이상)만 설치돼 있으면 됩니다. 패키지 설치와 빌드는 실행할 때 알아서 합니다.

| 환경 | 방법 |
|------|------|
| Windows | `start.cmd` 더블클릭 |
| macOS · Linux | `./start.sh` |
| 터미널 | `npm start` |

브라우저에 http://localhost:5179 이 열립니다. 끝낼 때는 실행 창을 닫거나 `Ctrl+C` 를 누릅니다.

- **바탕화면 아이콘 (Windows)**: `make-shortcut.cmd` 를 한 번 더블클릭하면 바탕화면에 `Quiz Word` 바로가기가 생깁니다. 이후에는 그 아이콘만 더블클릭하면 됩니다.
- 처음 실행할 때만 패키지를 설치하느라 1~2분 걸리고, 그다음부터는 바로 열립니다. 단어 파일이나 코드를 고친 뒤 다시 실행하면 자동으로 다시 빌드합니다.
- 이미 실행 중일 때 또 실행하면 새로 띄우지 않고 브라우저만 엽니다.

옵션은 뒤에 붙입니다 (예: `start.cmd --dev`, `./start.sh --lan`, `npm start -- --dev`).

| 옵션 | 설명 |
|------|------|
| `--dev` | 개발 서버로 실행 — 단어 파일(`data/words`)을 고치면 화면에 바로 반영 (`npm run dev` 와 같음) |
| `--lan` | 같은 네트워크의 휴대폰·다른 PC 에서도 접속 (접속 주소가 실행 창에 나옵니다) |
| `--no-open` | 브라우저를 자동으로 열지 않음 |
| `--rebuild` | 바뀐 게 없어도 다시 빌드 |
| `--help` | 옵션 안내 |

> 진행 기록(복습 일정·오답노트·통계·학습장)은 브라우저 localStorage 에 **localhost:5179** 기준으로 저장됩니다.
> 포트를 바꾸거나 다른 브라우저·다른 주소(`--lan` 의 IP 주소)로 열면 기록이 보이지 않으니, 옮길 때는 **설정 → 진행 기록 내보내기/가져오기**를 쓰세요.
> 그래서 포트는 5179 로 고정이고, 다른 프로그램이 이 포트를 쓰고 있으면 실행 창에 안내가 나옵니다.

## 기능

| 화면 | 내용 |
|------|------|
| 홈 | 오늘 복습할 단어·새 단어·오답 수, 주 시험의 문제 파일별 진척, 최근 7일 학습량 |
| 단어장 | 영어·한글 뜻 검색(`/` 키). **시험 → 문제 파일** 순으로 고르고, 품사·학습 상태·**단계**(`N단계 이상`)로 거름. 어느 시험 문제에도 안 나온 단어는 `확장` |
| 단어 상세 | 품사·발음기호·🔊 발음, 단계, 사전 뜻, **외우기**(어원·연상), **문제 속 뜻별 예문**(원문 + 해석 + 출처 문제 — 고른 문제 파일 것부터), 나온 문제 파일, 시험별 노트 |
| 플래시카드 | 시작할 때 시험 → 문제 파일 → 단계를 고름. 단어 → 안다/모른다 → 상세 → 다음. 뒷면 뜻 바로 아래에 **외우기**(어원 조각·어원 장면·발음 연상·같은 어근 단어). 모른 카드는 4~6장 뒤에 다시 나옴. 도중에 그만할 때 **진행한 단어**(진행 막대의 숫자)와 **남은 단어**를 각각 학습장으로 남겨 나중에 이어서 볼 수 있음 |
| 객관식 | 단어 → 뜻 / **문맥 뜻**(예문 속 다의어) — 오답 보기는 같은 품사·비슷한 뜻 분류에서 고름 |
| 복습 | FSRS 간격 반복. 시험일을 정하면 간격이 시험일을 넘지 않음. 새 단어는 설정의 **주 시험**에 나온 단어 가운데 **학습 단계** 이상에서 나옴 |
| 오답노트 | 틀린 단어 모음. 연속 2번 맞히면 자동으로 빠짐 (설정 가능) |
| 학습장 | 직접 고른 단어만 모아 반복 학습. 빈 학습장에서 시작하거나 오답노트를 통째로 복사해 시작. 학습장 안에서 단어장을 검색해 담고(`Enter`), 휴지통으로 바로 뺌. 학습장마다 플래시카드·객관식 (앱은 문맥 뜻도). **학습장 합치기**: 둘 이상 골라 겹치는 단어 없이 새 학습장으로 합치고 새 이름을 정함 — 기존 학습장은 남겨두거나 삭제 |

## iPhone · 안드로이드 앱

`mobile/` 에 같은 단어·학습 로직을 쓰는 앱(Expo)이 있습니다. iPhone 은 TestFlight 로, 안드로이드는 GitHub Actions 의 **Release** 워크플로가 Release 페이지에 올리는 APK 로 설치하고(Play 내부 테스트도 가능), 단어를 고치면 **단어 세트 파일**로 옮깁니다(빌드 없이):
웹 **설정 → 단어 세트 파일 내려받기**(또는 `npm run data:pack`) → 파일을 iPhone 의 파일 앱으로 → 앱 **설정 → 단어 세트 → 파일에서 불러오기**.
새 시험 하나만 더할 때는 **시험 팩**을 씁니다(앱 설정 → 시험 → 시험 팩 불러오기 — 아래 [새 시험 추가](#새-시험-추가)).
자세한 내용은 [mobile/README.md](mobile/README.md) 를 보세요. 웹과 앱의 진행 기록(학습장 포함)은 설정의 내보내기/가져오기로 옮길 수 있습니다.

## 데이터 구조

```
data/
  words/{a..z}.json            공통 사전 — 뜻·품사·발음·외우기·단계 (모든 시험이 함께 씀)
  exams/<시험 id>/
    exam.json                  시험 이름과 문제 파일 목록
    index.json                 단어 → 문제 파일별 나온 횟수 (그 시험에 속하는지, 얼마나 자주 나오는지)
    examples/<문제 파일>.json   단어 → 뜻이 정해진 예문
    sentences/<문제 파일>.json  문제 문장 전체 (예문이 없는 단어에 자동으로 붙이고 "더 보기"에 씀)
    notes.json                 단어 → 그 시험용 노트 (마크다운)
```

**예문이 나오는 순서** — 보고 있는 문제 파일의 예문 → 같은 시험 다른 문제 파일의 예문 → (붙은 예문이 없으면) 그 시험 문장에서 자동으로 찾은 문장. 그 시험에서 하나도 못 찾았을 때만 다른 시험의 예문을 보여 줍니다.

**단계(난이도)** — 모든 단어에 1~6단계가 있습니다: 1 초등 · 2 중학 · 3 고등 기본 · 4 수능 · 5 대학·공인영어 · 6 전문·기술. 단계마다 300~400개가 되도록 나눠서 교육과정 이름은 대략의 눈금입니다. 기준과 다시 나누는 방법은 `pipeline/prompts/level.md`.

## 단어 직접 추가·수정

단어는 `data/words/{첫 글자}.json` 에 있습니다(예: `escalate` → `data/words/e.json`). 배열에 항목을 추가한 뒤 다시 실행하면 반영됩니다. 고치면서 바로바로 보려면 `--dev` 로 실행하세요.

**최소 항목**

```json
{
  "id": "idempotent",
  "word": "idempotent",
  "level": 6,
  "pos": "형용사",
  "meaning": "멱등의 — 여러 번 실행해도 결과가 같은",
  "short": "멱등의",
  "domain": "상태·성질"
}
```

- 예문을 적지 않아도 시험 문제 문장(`data/exams/*/sentences`)에서 이 단어가 나온 문장을 **자동으로 예문으로 붙입니다**.
- 고친 뒤 검사: `npm run data:validate` (규칙은 `src/lib/checks.ts` — 시험 팩 검사와 같은 규칙)
- iPhone 앱에 반영: `npm run data:pack` → `wordset/` 에 생긴 파일을 앱 설정 → 단어 세트 → 파일에서 불러오기 (웹 설정의 '단어 세트 파일 내려받기'도 같은 파일)

**사전 필드** (`data/words`)

| 필드 | 필수 | 설명 |
|------|:---:|------|
| `id` | ✅ | 소문자·숫자·하이픈. 진행 기록의 키라서 **바꾸면 그 단어의 기록이 끊깁니다** |
| `word` | ✅ | 표제어 (여러 단어 구도 가능) |
| `level` | ✅ | 난이도 1~6 |
| `pos` | ✅ | 품사 배열 또는 `"명사·동사"` 문자열 — 명사, 동사, 형용사, 부사, 전치사, 접속사, 대명사, 한정사, 감탄사, 약어, 명사구, 동사구, 형용사구, 부사구, 전치사구 |
| `meaning` | ✅ | 사전식 한 줄 뜻 (`① … ② …`) |
| `short` | | 객관식 보기에 쓰는 짧은 뜻 (영어 없이 15자 안팎). 없으면 meaning 에서 만듦 |
| `domain` | | 의미 분류 (`src/lib/schema.ts` 의 `DOMAINS`). 오답 보기를 비슷한 뜻에서 고르는 데 씀. 없으면 `일반` |
| `ipa` | | 발음기호 (`/` 없이) |
| `senses` | | `[{ "pos": "동사", "ko": "다루다" }, …]` 여러 뜻 |
| `forms` | | 변화형·파생어 (검색·예문 찾기에 사용) |
| `synonyms` | | 영어 유의어 (객관식에서 정답과 겹치지 않게 오답 보기에서 뺌) |
| `memory` | | 외우기 — 플래시카드 뒷면·단어 상세에 나옴. 아래 예시 참고 |

시험에 딸린 것(`tier`·`basic`·`freq`·`sources`·`contexts`·`note`)은 사전에 적지 않습니다 — 적으면 `data:validate` 가 오류로 알려 줍니다.

**외우기(`memory`)** — `story`(어원으로 그린 장면)나 `hook`(발음 연상) 중 하나는 있어야 하고 나머지는 빼도 됩니다. 어원이 확실하지 않으면 `roots`·`origin` 은 적지 않습니다. 규칙은 `pipeline/prompts/memory.md`.

```json
"memory": {
  "roots": [{ "part": "de-", "ko": "떨어져, 멀리" }, { "part": "fer", "ko": "나르다" }],
  "origin": "라틴어 differre (따로 나르다)",
  "story": "일을 저만치(de) 날라(fer) 둔다 → 미루다",
  "hook": "디퍼 → '뒤로 퍼~ 넘긴다' → 미루다",
  "family": ["transfer", "refer", "prefer", "infer"]
}
```

> 외우기가 있는 단어는 1,794개입니다(2단계 이상은 전부). 그 가운데 **1,341개는 한꺼번에 생성해 형식 검사만 거친 것**이라 어원·연상이 틀린 것이 섞여 있을 수 있습니다. 틀린 것을 보면 그 단어의 `memory` 를 직접 고치면 됩니다.

**시험별 예문·노트 직접 고치기** (`data/exams/<시험 id>/`)

```jsonc
// examples/mock04.json — 단어 id → 예문. sense 는 그 단어 senses 의 ko 중 하나를 글자 그대로
"escalate": [
  { "n": 0, "q": 12, "en": "Escalate the ticket to a human.", "surface": "Escalate", "pos": "동사", "sense": "(상위 담당자에게) 넘기다", "ko": "티켓을 사람에게 넘긴다." }
]
```

- `n` 은 그 단어의 예문을 보여 줄 순서(작은 것부터), `q` 는 문제 번호입니다.
- `notes.json` 은 `{ "단어 id": "마크다운" }`, `index.json` 은 `{ "단어 id": { "문제 파일 id": 횟수 } }` 입니다.
- 문제 파일 목록은 `exam.json` 의 `sources`. `"kind": "wordbook"` 인 파일(기존 단어장 예문)은 예문만 있고 문제 파일 목록에는 나오지 않습니다.

## 새 시험 추가

두 가지 방법이 있습니다. 어느 쪽이든 **이미 있는 단어의 뜻·단계·외우기와 다른 시험은 그대로** 두고 새 시험만 더합니다.

| | (가) 시험 팩 | (나) 이 저장소의 파이프라인 |
|---|---|---|
| 필요한 것 | 문제 파일과 코딩 에이전트 — **이 저장소·기존 사전이 없어도 됨** | 이 저장소 + 문제 원본 폴더(`QUIZ_DATA_DIR`) |
| 결과 | `<시험 id>.exampack.json` 파일 하나 | `data/exams/<시험 id>/` 와 사전에 추가된 새 단어 |
| 앱에 넣기 | 앱 설정 → 시험 → **시험 팩 불러오기** (그 시험만 얹음) | `npm run data:pack` → 단어 세트 파일로 통째로 바꿈 |

### (가) 시험 팩으로

시험 팩은 시험 하나(문제 파일 목록·출현 횟수·예문·문제 문장·노트)와 그 시험이 쓰는 단어의 사전 항목을 담은 파일입니다. 만드는 방법·형식·검증기는 GitHub Pages(`docs/`)로 서비스합니다.

1. 코딩 에이전트에게 문제 파일과 **가이드 주소**를 줍니다: `https://swpark3179.github.io/Quiz-Word/exam-pack-guide.md` (지시문 예시는 `https://swpark3179.github.io/Quiz-Word/` 첫 화면에 있습니다). 문제 파일 형식은 무엇이든 됩니다.
2. 에이전트가 `<시험 id>.exampack.json` 을 만들고 검증기(`validate-exampack.mjs`)를 `RESULT: PASS` 가 나올 때까지 통과시킵니다. 검증기는 앱이 파일을 읽을 때 쓰는 검사와 같은 코드입니다.
3. 받은 파일을 넣습니다.
   - **iPhone 앱**: 파일을 폰으로 옮긴 뒤 설정 → 시험 → 시험 팩 불러오기
   - **이 저장소(웹)**: `npm run data:add-pack <파일>` → `data/exams/<시험 id>/` 가 생기고 새 단어만 `data/words` 에 들어갑니다

얹는 규칙 (앱과 `data:add-pack` 이 같습니다 — `src/lib/exampack.ts` 의 `mergeExamPack`):

- 팩의 단어를 id → 표제어 → (다른 단어의 변화형으로 등록된 표기) 순으로 사전에서 찾습니다. 단어 id 는 표제어를 소문자·하이픈으로 바꾼 값이라(`lay out` → `lay-out`) 사전을 모르고 만든 팩의 단어도 맞습니다.
- **이미 있는 단어는 그대로** 둡니다. 팩의 예문이 쓰는 뜻이 사전에 없을 때만 그 뜻을 덧붙입니다(괄호 보충만 다른 뜻은 사전의 뜻에 맞춥니다). 덧붙는 뜻은 불러오기 전 확인 창과 `data:add-pack` 출력에 나옵니다.
- 없는 단어만 사전에 넣습니다.
- 같은 id 의 시험이 있으면 그 시험만 바꾸고, 없으면 추가합니다.

반대로, 저장소에 있는 시험 하나를 팩으로 내보낼 수도 있습니다: `npm run data:pack-exam -- --exam ccar-f` → `wordset/ccar-f.exampack.json`.

**GitHub Pages 켜기** — 저장소 Settings → Pages → Build and deployment → Source: *GitHub Actions*. `main` 에서 `docs/` 가 바뀌면 `.github/workflows/pages.yml` 이 `docs/` 폴더만 그대로 사이트 루트로 올립니다(빌드 없음, Jekyll 없음 — 올리기 전에 예시가 검증기를 통과하는지만 봅니다). 저장소 루트를 올리면 안 됩니다: 루트의 `index.html` 은 Vite 개발용이라 빈 화면이 되고, 가이드 주소가 `/docs/…` 로 밀려 404 가 납니다.

| `docs/` 의 파일 | 내용 | 만드는 법 |
|---|---|---|
| `exam-pack-guide.md` | 에이전트용 가이드 | 손으로 씀 ("완성 예시" 자리만 자동) |
| `example.exampack.json` | 검증기를 통과하는 작은 예시 | 손으로 씀 |
| `validate-exampack.mjs` | 검증기 (Node 18+, 의존성 없음) | `npm run docs:build` — `src/lib/exampack.ts` 를 묶음 |
| `exampack.schema.json` | JSON Schema | `npm run docs:build` — 허용값을 `src/lib/schema.ts` 에서 가져옴 |
| `index.html`, `llms.txt` | 사람용 첫 화면(브라우저 검증기), 에이전트용 길잡이 | 손으로 씀 |

검사 규칙(`src/lib/checks.ts`, `src/lib/exampack.ts`)이나 품사·분류·단계를 고쳤으면 **`npm run docs:build` 를 다시 돌려 커밋**합니다. 잊으면 `npm test` 가 알려 줍니다.

### (나) 이 저장소의 파이프라인으로

문제 원본(`QUIZ_DATA_DIR`, 기본값은 PC 의 `Quiz-Bank/assets/quiz-data`)에 새 시험의 문제 파일이 있을 때 씁니다. **사전을 통째로 다시 만들지 않습니다** — 새 단어만 사전에 추가하고, 그 시험 폴더(`data/exams/<id>`)만 새로 씁니다. 이미 있는 단어의 뜻·단계·외우기와 다른 시험 데이터는 그대로입니다.

1. `pipeline/exams.json` 에 시험을 적습니다.
   ```json
   { "id": "my-exam", "name": "내 시험", "order": 2, "set": "my-exam", "exclude": ["-kor$"] }
   ```
   `set` 은 문제 원본 `config.json` 의 id(= 문제 파일 폴더 이름), `exclude` 는 쓰지 않을 문제 파일 id 의 정규식(한글판 등)입니다.
2. `npm run data:extract -- --exam my-exam` — 문제 파일에서 문장과 단어 원형을 뽑음 → `pipeline/work/my-exam/`. 사전에 이미 있는 단어는 `known` 으로 표시됩니다.
3. `npx tsx scripts/build-batches.ts --exam my-exam` / `npx tsx scripts/build-batches-b.ts --exam my-exam` — LLM 생성용 배치 입력
4. 배치마다 `pipeline/prompts/passA.md`(이미 있는 단어는 예문·문맥 뜻만, 새 단어는 뜻·단계·외우기까지), `passB.md`(문장 해석) 지시대로 생성 → `pipeline/work/my-exam/gen/`
5. `npm run data:merge -- --exam my-exam` — 새 단어를 사전에 추가하고 `data/exams/my-exam/` 을 씀. 확인할 것은 `pipeline/work/my-exam/merge-warnings.txt`
6. `npm run data:validate`
7. 앱에 반영: `npm run data:pack`(또는 웹 설정 → 단어 세트 파일 내려받기) → iPhone 앱 설정 → 단어 세트 → 파일에서 불러오기

이미 있는 시험의 문제 파일이 바뀌었을 때도 같은 순서로 그 시험만 다시 돌립니다(`--exam ccar-f`). `merge` 는 그 시험 폴더를 통째로 새로 쓰므로 **`data/exams/<id>/` 를 직접 고친 내용은 덮어써집니다**.

그 밖의 데이터 명령:

| 명령 | 하는 일 |
|------|---------|
| `npm run data:levels` | `pipeline/work/levels/scores-*.txt` 의 점수로 단계를 다시 나눔 (`-- --write` 로 사전에 반영) |
| `npm run data:memory` | `pipeline/work/memory/out-*.json` 의 외우기를 검사해 사전에 반영 (이미 있는 것은 그대로, `-- --check` 는 검사만) |
| `npm run data:migrate-check` | 지금 `data/` 가 구조를 바꾸기 전 데이터와 같은 내용인지 전수 비교 |
| `npm run data:add-pack <파일>` | 시험 팩을 `data/` 에 합침 (새 시험 폴더 + 새 단어만) |
| `npm run data:pack-exam -- --exam <id>` | `data/` 의 시험 하나를 시험 팩 파일로 |
| `npm run docs:build` | `docs/` 의 검증기·스키마를 다시 만듦 (`-- --check` 는 최신인지 확인만) |

## 개발

- `npm run dev` — 개발 서버 (`npm start -- --dev` 와 같음) · `npm run build` — 타입 검사 + 빌드
- `npm test` — 단위 테스트 (오답 보기 생성, 플래시카드 대기열, SRS, 검색, 학습 범위·학습장, 시험 데이터·예문 고르기, 진행 기록 스토어(모아 쓰기 포함), 단어 세트 파일, 문장 분리, 실행 스크립트, 가짜 시험으로 돌리는 추출 → 병합 → 검사, 시험 팩 검사·얹기, `docs/` 의 가이드·스키마·검증기가 코드와 맞는지)
- `npm run smoke` — 앱을 띄운 상태에서 설치된 Edge 로 주요 화면을 눌러 보고 스크린샷 저장 (`BROWSER=chrome` 또는 `BROWSER_PATH=실행 파일` 로 브라우저 지정)
- 실행 스크립트는 `scripts/launch.mjs` 이고 `start.cmd`·`start.sh`·`npm start` 가 모두 이것을 부릅니다
- 스택: Vite + React 19 + TypeScript, Tailwind CSS v4, zustand(localStorage), ts-fsrs, Pretendard
